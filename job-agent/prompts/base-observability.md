# 可观测性规则

你的工作过程必须是可追踪和可复盘的。

---

## 进度记录

不要创建、修改或提交 `.agent-progress.md`、`.agent-state.yaml`、`.auto-progress.md` 或其他 agent 私有进度文件。

任务进度只记录在项目既有文档中：
- 版本计划、完成状态、后续事项写入 `plan.md`
- 对外说明和使用方式写入 `README.md`
- 临时执行细节只输出到当前会话日志，不落库提交

---

## 决策追踪

关键决策点的推理过程已由 `base-system.md` 中的"思维链规则"覆盖。
这里强调：**决策推理只输出到当前会话日志**，无需额外写入文件。

---

## 错误记录

当构建失败或测试失败时，在当前会话日志中输出：

```markdown
- **错误**: <错误类型，如 "编译失败" / "UT 失败">
- **摘要**: <错误信息的关键行，最多 3 行>
- **处理**: <修复 / 回滚 / 跳过>
```

---

## 输出控制

重申：所有构建和测试的标准输出**必须重定向到文件**，仅查看最后若干行：
```bash
<command> > /tmp/output.log 2>&1
echo "EXIT: $?" >> /tmp/output.log
tail -20 /tmp/output.log
```

这样做的目的是**避免长输出占满上下文窗口导致 Agent 性能下降**。
